\section*{Discussion}

The core insight is that relevance is not applicability. Retrieval can return a
well-supported statement while a system still applies it to the wrong time,
scope, epistemic state or possible world. Situation engineering turns this
failure from an informal complaint about ``missing context'' into a set of
state variables, update rules and behavioural consequences that can be tested
separately.

\subsection*{A complementary layer, not a replacement vocabulary}

The situation contract of equation~(\ref{eq:contract}) is meant to prevent
conceptual inflation. Retrieval quality should not be
renamed situation engineering, and a JSON field named ``situation'' is not
evidence of situation awareness. A system must show that state representation
causally changes behaviour in predicted cases, that state uncertainty affects
answering or action, and that failures can be assigned to sensing, update,
validation, policy or generation.

\subsection*{Implications for hallucination and agent evaluation}

A generated claim can be entailed by a document yet wrong for the query, so
evaluation should record both support and applicability. Generated claims
should be linked to the state and provenance on which they depend; agent tools
should expose preconditions and state transitions, and harnesses should block
consequential actions while answer-critical state is unresolved. Clarification
and abstention are correct when the situation is under-specified, so
evaluations should report clarification utility, unnecessary questions,
selective risk and cost alongside accuracy.

\subsection*{What is established and what remains to be tested}

This study defines a formal error class and an interoperable state schema
whose matched ablations have category-specific effects, and shows that
performance degrades sharply when state must be recovered from text, making
situation sensing a separate engineering and evaluation target.

Of the framework's predictions, the controlled ones hold: corrupting or removing
one state variable damages only its matching category, and predicted-state
errors decompose into sensing rather than update or policy failures. The first
neural prediction does not hold at the prompt level: an explicit situation state
did not improve the categories whose decisive variables it names. This is
consistent with gains vanishing when a baseline such as the structured prompt
already represents the same state, but it shows no benefit of situation
prompting itself. The
sensing prediction is also only partly borne out: language-model sensors
remove most of the rule sensor's errors, so in this benchmark the residual
sensing gap is mainly information the text does not contain. On natural
questions the date or place itself, not the situation prompt, carries the gain
(E8b, E9); confirming the general claim requires natural evidence for every
category under matched model, evidence and budget (Methods). The SE0--SE4
maturity model and longer research programme are provided in Supplementary
Information.

\subsection*{Limitations and risks}

The diagnostic data are generated from a schema shared with the solver, so
benchmark-solver circularity is intentional and limits external validity. The
item count does not equal the number of statistically independent observations
because examples share template
families. The E1--E4 baselines are software controls. The model studies cover
no proprietary family other than Gemini, test natural text only on temporal
and geographic questions with two models, and two results rest on post-hoc analyses (scoring
sensitivity; output truncation). Balancing
answers and claim recency removes the shortcuts found in v0.1, but each
category still varies only one or two template factors, so other surface
regularities may remain. Confidence
values are rule-derived and do not constitute neural calibration. Human
agreement rests on three volunteers and 70 items: Fleiss' $\kappa$ is 0.92 for
the possible world and 0.72 for the answer, 0.20--0.49 for the other state
slots, and $-0.07$ for temporal relevance, an ambiguous codebook item (Methods). No multilingual, multimodal or deployed-agent study was
completed. Earlier and aborted runs are archived but excluded from
scientific results; only the complete run that passes the integrity gate
enters the manuscript.

Explicit state can also create new attack surfaces. An adversary may manipulate
timestamps, source authority, identity, scope or world labels. A centralized
state representation may expose sensitive user information or create false
confidence in a flawed schema. Situation-engineered systems therefore require
provenance, access control, privacy-preserving memory, conflict visibility and
independent evaluation. ``Explicit'' must not be confused with ``correct''.

\subsection*{Conclusion}

Situation engineering provides a bounded and testable interface between
retrieval, state estimation and response policy. The controlled experiments
demonstrate that applicability variables have distinct behavioural consequences
and that imperfect sensing can erase the advantage of correct update rules.
Establishing broad utility now requires the pre-specified natural-text,
multi-model comparison against equally resourced structured prompting,
temporal retrieval and agent verification.
